# 热图时序与逐帧 foveation 初步试验（2026-11-05）

本轮先检查模型能否读取输入中表示的注视位置与时间先后。热图希望减轻第一视角头动与多帧时序关联的负担，foveation 希望突出每帧的局部细节；二者均为待验证假设。此试验不计算最终 referent Exact-set/F1，不把显示线索的读取精度当成真实 gaze-to-object 定位精度。

## 固定输入与条件

开发小样本固定为 scene1/261、scene2/411、scene3/577、scene4_room1/72、scene5/28。选择沿用讨论时指定的五个场景和受支持时钟条件，不是总体随机性能估计。每条使用原24交互审计的全部12帧，覆盖低/中/高头动，保留无姿态/无时钟支持帧。60张源帧中56张有受支持的注意时钟，4张在全部条件中保持相同RGB。

时钟/姿态直接读取已有 `frame_pose_contract.json`，图片SHA-256、遥测SHA-256、真实PTS与 `query + offset = PTS` 均核对。即时 gaze 使用原始遥测中的最近有效样本，容差0.18秒；它可能略晚于参考时刻，因此本轮是离线分析。历史 gaze 严格只取参考时刻前2秒，按同一参考姿态重投影，使用已有持续时间权重和2°空间核。样本准备显式 `load_ground_truth=False`，不读取旧referent投影图，不进行任何anchor投影。

| 条件 | 内容 |
|---|---|
| RGB | 原始RGB，无gaze crop |
| INSTANT_HEATMAP | 单帧最近 gaze，固定尺度的橙红热图 |
| HISTORY_HEATMAP | 过去2秒注视的单色累计热图，保留密度但不显式区分先后 |
| ORDERED_HEATMAP | 同一历史图分为三个等长时间段；蓝=旧、黄=中、橙红=新 |
| REVERSED_TIME_HEATMAP | 同一三段热图反转颜色时间语义；坐标、总热度与逐像素透明度不变 |
| INSTANT_FOVEATION | 只用当前 gaze 调整每帧细节，保持0.55原图成分下限 |
| ORDERED_PLUS_FOVEATION | 当前 gaze 的 foveation 加有序历史热图 |

分时热图直接显示各段的高斯核密度，不在离散观测间补画连线，不假定历史交点仍对应当前可见对象。未做逐帧峰值归一化。显示尺度2.0、alpha上限0.50；这是固定的初步可读性参数，不是已优选的强度。

七种条件的源帧、顺序、PTS、提示和图像尺寸一致。每张RGB先缩为448×448，再加32像素的独立ID/PTS标题；模型坐标包含标题，保存的评分坐标也做同一变换。使用12张按时间排列的独立图像输入，避免视频编码把相邻两张源帧合成同一个时间patch后再要求精确逐帧引用。本轮不是密集视频端到端结果。实际processor token和真实vision输入哈希随请求保存并核对。

## 模型输出与评分

所有条件使用同一提示，给出原交互指令作上下文。逐帧输出最强可读cue中心、最旧蓝区和最新橙红区的位置，以及cue附近的可见物体/区域描述。提示允许返回null，明确自然物体颜色不算gaze标记，不能仅凭指令猜物体。

- 热区中心命中：误差不超过输入图片对角线的10%。缺失、null、重复帧ID或不完整schema都保留在分母，不能通过少答获得好分数。
- 无cue误报：RGB和各条件实际回退帧中，仍输出坐标的数量。
- 时间区分：只在最旧/最新区域均存在、两者主峰相距至少10%对角线的帧上，报告两个区域同时命中的比例；当前有24张此类帧。资格由刺激生成决定，在推理前固定。
- 单独分低运动(<10°/s)、中等(10–45°/s)、快速转头(≥45°/s)；这些是显示cue的读取差异，不是目标投影误差。

同一画面可以有多个同等峰，评分暂时以确定性的主峰为参考，因此只用于探索性诊断。可见物体描述尚无独立人工区域标注，只保存供复核，不自动当正确答案。真实与反向热图之间读取结果是否随颜色改变，也只能表明模型对表示敏感，不能证明模型获得了动作/mention时间关联能力。

## 工程验证

60帧/420张条件图已生成；历史分箱之和与原始累计图一致、反向颜色逐像素alpha一致、不支持时钟时七条件哈希相同。三个定向测试通过：时间反转与因果窗口、零图RGB一致、缺失/重复帧不排除分母。模型结果已完成，见下文与产物 `RESULTS_zh.md`。

## 独立合成正对照

在固定scene2/411的真实RGB上另加大而醒目的蓝/橙高斯色块（sigma=20输入像素、峰值alpha=0.95），四个位置按帧交替，正/反颜色两组使用同一读取提示。位置与gaze/GT无关，且帧间变化明显超过评分阈值，不能靠复制固定坐标获得全部命中。它是在首批真实条件多次返回null/重复坐标后增加的探索性诊断，不并入真实gaze七条件指标。

若合成对照中旧/新同时命中不足一半，再使用一张图和简化的颜色定位提示检查单帧读取能力；这个不同提示的诊断也单列结果。代码为 `tools/run_heatmap_readout_positive_controls.py`，生成/推理入口分别为无参数和 `--infer`。

## 完成结果

35/35真实gaze请求完成，35/35完整12帧schema，35/35真实vision输入核对通过；实际视觉token全部2520。关键源码与模型配置快照未变。另有两组12帧合成正对照和一个单帧简化诊断，共38次本地请求，无远程API。

| 条件 | 中心命中（≤10%对角线） | 旧/新同时命中 |
|---|---:|---:|
| 即时热图 | 0/56 | 不适用 |
| 累计热图 | 0/56 | 不适用 |
| 分时热图 | 4/56 | 0/24 |
| 时间颜色反向对照 | 0/56 | 0/24 |
| 即时foveation | 0/56 | 不适用 |
| 分时热图 + 即时foveation | 5/56 | 0/24 |

RGB无cue误报0/60。组合图回退帧误报1/4。分时热图的11个非空中心全部来自scene2/411且重复 `[650,520]`；组合图多次把半透明手部形状描述为cue。因此这9个粗阈值命中不构成稳定追踪证据，也不能解读为性能提升。

醒目合成正/反颜色在相同12帧提示中焦点命中分别4/12和5/12，但旧/新区域分别都0/12。单张图配简化颜色定位提示返回蓝 `[210,768]`、橙 `[250,278]`（归一化1000坐标），对应主峰像素误差12.8与13.7px。该对比说明有必要先拆解cue读取和跨帧关联；帧数与提示复杂度同时改变，不能只归因于多帧输入，更不能据此否定热图缓解头动/时序干扰的研究动机。

下一步优先用固定帧分别检查“颜色/区域读取”和“时间关联”两个任务；待读取可靠、人工核对少量gaze-to-object对应后，再接最终指代评价。当前多色图未建立时序可读性，foveation未建立局部焦点可读性。详细运动分层、分母和原始响应见 [本地结果报告](../.local-sync/heatmap_temporal_pilot_20261105/RESULTS_zh.md)，图集见 [交互预览](../.local-sync/heatmap_temporal_pilot_20261105/index.html)。

## 后续原因复核

显式cue坐标失败不等于模型内部完全未利用cue。代码/数值复核确认：本轮即时foveation的focus峰值仅0.199–0.241，导致全部有效帧所有像素都选最粗的8倍模糊层；焦点原图混合权重中位0.640，周边0.550，没有形成明显清晰中心。另有12帧复合提示与单帧简化提示的混杂。详细证据和下一轮2×2隔离设计见 [原因分析](../.local-sync/heatmap_temporal_pilot_20261105/CAUSE_ANALYSIS_zh.md)。此复核未新增模型调用、未修改旧实验实现。

## 用户最新约定：脚本处理图像，模型集中做语义判断

此次讨论调整后续研究分工，不修改已完成的v1结果，也尚未执行新的推理方案：

| 脚本直接计算/完成 | 模型保留的判断 |
|---|---|
| 视频PTS/遥测配对、姿态重投影、gaze有效性与数值汇总 | 当前证据区域内的可见物体与属性 |
| 区域选择、图像增强/裁剪、foveation清晰区构建 | 同类对象比较、语言mention与视觉对象的关系 |
| 时间排序、原图区域映射、证据来源记录 | 必要的跨帧对象语义对应，不预设坐标连续就等于同一对象 |

不再让模型反推脚本已经知道的热点坐标、颜色时间或焦点中心。颜色/坐标读取结果保留为诊断，不能作为热图/foveation是否有效的最终判据；原先建议的2×2读取实验降为可选调试，不占主线优先级。

热图作用保持待定：一条候选路线是作为脚本内部的注视权重来组织/处理RGB；另一条是作为可选视觉叠加线索输入模型，检验其额外收益。尚未选择呈现方案，也不预设热图一定有用或必须被模型显式解释。两条路线均需保留短时历史和源帧时间对应，不自动退化为全交互单个gaze crop。

后续模型输出应围绕可见对象与指令关系，主要评价回到原指代任务；头动分层、时间负对照用于核查是否缓解原始干扰。审计仍只展示本交互referent投影，模型输入不使用GT选择区域。
