# 转头下统一热图：固定方向坐标与视觉筛选（2026-11-06）

> **后续修正**：六面预览发现水平采样偏移，已修复并增加方向像素测试；旧模型请求使用经纬展开图，未受该预览错误影响。修正版预览与后续实验见 [透视注意筛选与RGB回接](PERSPECTIVE_ATTENTION_ROUTING_20261106_zh.md)。本文件记录的原始输入/结果保留。

本轮将头动后的多个画面统一到固定方向坐标，保留热图的图像输入性质，并让模型根据视觉热点选择优先检查的RGB区域。实现了球面时空密度、带源帧索引的角度RGB图集、六面透视显示、相机视野移动演示及两轮视觉布局检查。

**结论边界**：固定方向坐标解决“历史不能只存在于当前画面范围内”的表示问题；它没有解决身体平移视差、遮挡、动态物体或最终对象身份。模型实验是视觉注意区域筛选探针，不是完整referent任务。

## 用户问题对应的两个范围

- **瞬时视野**：某个时刻的相机朝向与FOV决定的一张画面。图像的像素宽高不是跨时间的空间坐标。
- **累计视域**：转头过程中，各时刻视野在共同坐标中的并集。它可以比任何一张画面更大，也可以是不规则、有空洞的区域。

同一物体可能在转头时从画面右边移到中间；因此不能把所有帧相同像素坐标处的gaze直接相加，也不能只保留还能投进末帧的历史。另一个独立问题是设备实际可见范围大于录制相机范围：没有记录的RGB无法由热图恢复，必须保留为图像未知。

## 固定方向热图的构造

每个交互使用**第一张时钟受支持的源帧姿态**作为固定方向参考，后续查询不重新居中。采用360°水平、180°垂直的球面存储，只作为坐标容量，不表示用户实际看遍360°。

本数据的gazePoint/gazeVector沿用现有世界坐标约定：有限点先减去该观测时刻相机位置，得到世界方向；世界gazeVector直接使用。再乘固定参考姿态旋转的逆，转成参考方向。**不把世界方向再次乘当前头部姿态**。若输入本身是相机局部方向，才需要先转换到世界坐标。

经纬度角图显示的是这些方向的展开：

- 水平为yaw、垂直为pitch，坐标在整个交互中固定。
- gaze支持时长以秒累积，分为旧、中、新三层；每个核按球面单元的立体角归一化，三层总质量保持支持秒数。
- 球面水平接缝周期连续；两极用立体角权重防止面积失真。单元存的是质量，显示强度使用单位立体角密度。
- 相机视野覆盖单独存储。即使眼动无效，相机仍可覆盖该方向；没有gaze不等于没拍到，没拍到也不等于没注视。
- 保留缺测间隔、无效观测、时钟回退以及未来观测隔离。

**平移限制**：此处是方向图，不是三维表面图。相机位置改变时，同一个近处物体的世界方向也会改变；身体移动不能仅靠球面方向抵消。可靠深度/静态三维对应可用于后续表面累积，动态对象仍需额外对应。本轮没有把这些条件假设为已满足。

## RGB与热图如何在共同坐标中对应

保存下来的各真实RGB帧，根据各自相机旋转和FOV，作为方向窗口采样到同一球面。每个图集像素记录来自哪张源帧，重叠处使用较晚源帧；未被源帧覆盖的方向保持深色未知。不生成额外RGB。

这是**按旋转查找真实帧的角度图集**，不是完整几何全景重建。窗口接缝、平移视差、动态物体和半透明手都可能形成错位，不能把拼出的外观当作同一时刻的场景。热点来自其观测时间，图集背景RGB可能来自另一个时间，原始帧必须保留。

提供两种图像显示：

1. **角度展开图**：方便看累计覆盖和整段热点。极点附近会拉伸；画面横跨360°有时只是极点展开，不代表实际转了一整圈。
2. **六面透视图**：同一球面显示成前、右、后、左、上、下六个90°窗口，减少极点拉伸。方向相对固定参考姿态，不是地理方向。仍只显示已记录RGB。

交互演示 `head_motion_demo.html` 使用整段离线热图/图集，滑块只移动某个原始帧的相机视野白框。历史热图保持固定；点击方向图可以按像素源帧索引回查RGB。**滑块不代表实时推理，也没有随时间截断热图**，避免把整段离线信息冒充当时可得信息。

## 实际样本与几何检查

使用已有24交互的PTS/姿态合同；13交互有足够支持，11交互保持RGB回退，共142张时钟受支持的原始帧进入图集。所有时钟、图像哈希和查询时间沿用既有统一入口。没有加载GT或投影anchor。

这13交互相对起始姿态的最大旋转约12.9°–68.0°，已记录相机位置变化约0.037–0.192世界单位。不能因此忽略近物体视差。

例如scene2/411，固定方向热图中约56.5%的密度质量仍在末帧方向窗口内，其余保留在球面其他方向；scene4_room1/72约53.4%。这些是角度模型与工程核的积分，不是人工验证的物体可见率或注视准确率。

本轮使用整个受支持事件范围，按其长度分旧、中、新三段，**不是上一轮固定两秒窗口**；两轮模型布局使用完全相同的密度，不与之前实验数值直接拼接。

## 热图仍以图像输入模型

没有把注视权重转换成候选文本。输入包含：

- 固定坐标中的RGB及三个标记区域A/B/C；区域是角度范围，不是对象ID。
- 共享坐标的早、中、晚三张热图。
- 简短的版式和颜色说明，不含候选数值分数、真实目标、指令或GT。

模型只选择早期与晚期应优先检查的RGB区域，依据图上最亮的附加热峰，输出两个区域ID。不要求坐标，也不把最高热点直接标为referent。脚本保存峰值判定和质量积分判定，二者不是同一个指标；本探针明确评价最亮峰值所在区域。

四种条件在同一RGB下比较：真实热图、时间层反转、空间错移、无热图。时间反转和空间错移都按其实际显示的新热点评分，不能以原始热点强迫评分。无热图应输出none。

## 两轮布局迭代结果

13交互×4条件×2布局，共**104/104次本地Qwen3-VL-8B BF16请求完成**；每次实际1024视觉token，输入tensor进入vision forward均核验。固定输入、提示、期待区域和输出均保存。两轮都使用同批事件，第二轮是看过第一轮错误后的布局迭代，**没有新留出验证**。

| 图像条件 | 初版早/晚同时正确 | 调整布局后早/晚同时正确 |
| --- | ---: | ---: |
| 真实热图 | 11/13 | 10/13 |
| 时间反转，按反转后的图评分 | 10/13 | 11/13 |
| 空间错移，按错移后的图评分 | 11/13 | 10/13 |
| 无热图，早/晚都正确拒答 | 3/13 | 13/13 |

初版把RGB局部放在热图之后，无热图的晚期结果经常被猜成某个区域。第二轮把全部RGB放在三张明确命名的热图之前，并加强“无橙色即none”的提示。拒答改善与**版式和提示同时变化**有关，不能单独归因于挪动图像。

空间错移后，两轮全部13交互的模型输出发生变化，支持模型输出受热图图像影响；并不证明正确理解了用户意图。真实早/晚优先区域不同的只有4交互，时间反转后两轮各有2/4完全正确。其余事件早晚区域相同，不能将10/13或11/13写成稳定的时间理解能力。

还没有验证真实对象候选筛选、mention对应、同类对象身份或最终Any-hit/Exact-set/F1。未知区域拒答、角度图畸变、区域过粗和手部干扰仍然存在。
