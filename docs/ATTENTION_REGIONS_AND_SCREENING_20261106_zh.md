# 连续关注区域、原生 RGB 与指令筛选（2026-11-06）

本轮把“读最亮方向”的诊断进一步拆开：脚本从完整球面提取多个连续关注区域、绑定原始时间和 RGB；模型查看 RGB、图形热图和原始指令，判断候选是否值得保留。热图始终作为图像，未把注视权重或预期答案转成候选文本分数。

**结果**：修正了上一轮把显示窗口当成独立热点的判定；新的连续区域在相同代表点数量下略多覆盖注视方向，但热图附加显示仍没有可确认的语义筛选收益。不能把区域覆盖率或模型输出格式合规当成具体物体/最终 referent 的准确率。

## 1. 对上一轮结论的修正

上一轮最多两个方向的任务，以六个立方体面的密度峰决定“应保留双方向”。方向窗口的切分与用户实际关注区域并不一致：

| 旧双方向案例 | 两面峰方向夹角 | 在完整球面半峰包络中是否连通 |
| --- | ---: | --- |
| scene2/71 晚段 | 1.04° | 同一连通热区 |
| scene4_room1/72 晚段 | 5.62° | 同一连通热区 |
| scene2/411 早段 | 31.95° | 两个分量 |
| scene2/678 早段 | 63.55° | 两个分量 |

因此，原文“4个应保留两个热点全部漏选”需要收窄为“4个满足旧双面峰规则的案例均未同时保留两面，其中2个是同一连续热区跨面”。其余2例的真实分离热区仍未得到完整保留，模型多候选读取问题没有因此消失。

反过来，26个早晚时间段中有8个时间段存在多个半峰连通分量的峰落在同一面内，原先的方向输出也无法区分它们。scene2/411 早段的第二个热区本身还跨 FRONT/RIGHT，面内峰与完整热区峰并非同一个点。连通分量也不等于对象或 fixation。

旧提示说“第二峰约为最亮峰一半亮度”，评分却比较原始密度；渲染用了平方根 alpha，亮度比与密度比并不一致。本轮不再让模型估计该阈值，也不追改历史图片和响应。

## 2. 新的空间提案与时间组织

新增 `MultiAgent/attention_regions.py`：

1. 保留受支持时钟、固定参考球面和三等分时间窗；不随当前头部视角重新居中。
2. 在每个时间段按“秒/球面立体角”的密度排序，找包含至少90%支持时长质量的最高密度包络；边界同密度并列全部保留。
3. 在完整球面上做连通区域提取，连接经度周期边界和极点接触；没有六面显示切割，不设 top-k，不预设物体数量。
4. 为每个区域仅从自身实际 gaze 观测中选一个代表观测；没有观测就保留失败状态，禁止换成其他更强区域。
5. 复用原时钟，在原视频完整解码 PTS 中找最近、且不晚于时间段结束的真实源帧，按解码帧号提取。
6. 以该源帧相机方向采样早/中/晚完整角度密度，形成同一 RGB 裁剪对应的三张热图。局部范围包含源帧内可见包络，至少18%画幅，并保留全帧上下文。

13条旧交互、39个时间段，共 **115个区域**；114条形成原生 RGB，1条 scene2/678 晚段代表 gaze 投影超出源帧上边缘，状态为 `NATIVE_GAZE_PROJECTION_UNSUPPORTED`。最大实际帧 PTS 与 gaze 时间差 **35.16ms**。没有改时钟拟合、没有投影场景 anchors，也未加载对象 GT。

总支持质量约83.882秒，包络约75.544秒，剩余约8.337秒仍在 `regions.npz` 的完整 `duration_maps` 和显式 `residual_maps`，没有删除原始观测。这里的90%是平滑核积分的质量比例，不是删除10%的 gaze 样本；按观测中心落入包络统计，本批覆盖约99.82%的观测支持时长。

每个区域仅有一个代表帧不能覆盖其完整空间范围、遮挡变化或动态对象。跨时间段的区域未做对象身份合并，同一对象可重复出现；低密度/未观看对象仍可能是语言目标。

## 3. 几何覆盖：增加预算与改变分区分别报告

对相同26个早/晚时间段，用代表 gaze 方向附近4°/8°/12°范围覆盖的实际观测支持时长做工程诊断。该角度阈值不是物体边界或校准误差。

先逐时间段匹配数量：`min(2, 有实际观测的粗方向数, 已成功回接的连续区域数)`；两种方法都按支持质量排序，每个区域取自身局部峰附近的真实观测，不调用模型。两者总计均为36个代表点。

| 方法，均36代表点 | 4°方向覆盖 | 8°方向覆盖 | 12°方向覆盖 |
| --- | ---: | ---: | ---: |
| 粗六面方向，脚本选择 | 61.68% | 67.98% | 72.13% |
| 完整球面连续区域 | 63.96% | 71.26% | 75.76% |

8°提升约3.28个百分点，只是该批旧样本的小幅几何改善；没有独立样本、不做显著性或头动因果收益声明。

另作预算扫描：连续区域 top1为26点、8°覆盖61.41%；最多两区域50点覆盖83.64%；全部已回接早晚区域83点覆盖91.61%。旧模型最多两面为27点、覆盖61.06%。后者的预算不同，不能把61%→92%写成算法等预算收益。

事后包络阈值检查：80%/90%/95%分别127/115/111个区域。包络扩大时分量会连接，所以数量不单调增加，更不能把分量数当物体数。正式实验始终固定90%。

## 4. 六候选同页：停止并保存失败

初版按六张候选卡/1008方图，让模型为每个 ID 返回 keep/review/reject 和简短内容；下方保留该候选的早/中/晚热图。原计划72次。

前15次完成后，出现5次 schema 失败：模型插入未要求的 bbox 条目或重复生成；合规输出也常是全 `review/unclear`。主动停止其余请求，未修剪非法字段来伪装成功。另有1条请求在输入/追踪写入阶段被中断，不计为完成推理。`stopped_early.json`、原响应和缓存均保留。

不能只把失败归因于缩略图尺寸：后续同时修改了图片面积、每次候选数、提示与输出 schema，因此不是纯分辨率消融。

## 5. 单区域放大、原始指令相关性筛选

每交互在模型调用前固定选择三条：早段支持质量最大、晚段最大、其余区域质量最大；共39条。其余75条可用区域仍在完整记忆中，本轮未做完整语义筛选。每张输入1008×1008：源帧上下文与局部详情各448见方，下方早/中/晚热图各288见方，热图与 RGB 详情使用同一原生相机方向和裁剪。

模型仅输出具体可见内容 `visible` 与 `relevance=plausible/unclear/unrelated`，结合 CSV 原始指令，不提供 anchors、对象 GT、注意分数、期望答案或热图峰标签。模型只作语义审阅，全部原始候选始终保留，未将 `unrelated` 接成默认硬删除。

三个条件：真实热图、无新增热图、反转早晚。所有条件共享 gaze 派生的裁剪、源帧、源时间和源视频自带的绿色标记。因此无热图只检验**额外显示热图**的作用，绝不是不使用 gaze 的基线。

先做6条历史开发交互54次，保存 `development_frozen.json`，不改参数后再跑7条历史检查交互63次。所有13条均已在此前多轮出现，两个子集都只属于回归检查，没有独立未见验证。

| 条件 | 完成调用 | plausible | unrelated | unclear | 相对真实热图的相关性变化 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 真实热图 | 39 | 16 | 23 | 0 | — |
| 无新增热图 | 39 | 18 | 21 | 0 | 2/39 |
| 时间反转热图 | 39 | 18 | 21 | 0 | 2/39 |

117次均符合新 schema，并返回了非字面 `unclear` 的视觉描述；这仅说明任务能执行，描述和相关性并未有人工GT核验。已观察到“描述中出现椅子，却判与含椅子指令无关”等明显值得复核的结果，不能自动相信拒绝意见。

检查部分21个区域三条件相关性完全相同。开发部分少量变化主要伴随模糊物体的解释改变（箱子/建筑、手/无人机、椅子部件），没有证据说明变化更准确。

**不能据此说模型内部完全没用热图。** 当前任务判断与整条指令是否相关，本来就可能对时间反转保持不变；没有 mention 时间 GT 和动作阶段标签，不能拿反转不变证明时间理解失败，也不能拿输出改变证明理解成功。目前能说的是：本任务和本批数据尚未展示附加时序热图的可确认收益。
