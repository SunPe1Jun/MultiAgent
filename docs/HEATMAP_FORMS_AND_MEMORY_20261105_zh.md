# 热图的构造、呈现与使用：扩展尝试（2026-11-05）

本轮把热图扩展为“时间分层的数值证据 + 可选视觉呈现 + 脚本组织的历史RGB”，实现并测试了多种使用方式。主要工程发现是：历史不应只存在于当前RGB坐标中；当前投影被判画外的观测，仍应有独立的原生帧记忆。但新的轮廓、聚光、自适应裁剪、原生历史局部均没有稳定的语义识别提升，尚不能替换默认完整流程。

原始模型输入、响应、标签冻结和核验记录位于 `.local-sync/heatmap_forms_v2_20261105/`。当前推荐查看：

- `index.html`：六种呈现逐帧对照，显示模型输出和预先冻结的复核类别。
- `temporal_memory.html`：固定旧、中、新三段的当前重投影和历史原生RGB对照。
- `native_attention_memory.html`：按注视方向变化自动分段的历史局部原型，尚未跑语义模型。
- `offscreen_attention_memory.html`：当前投影画外历史的保留示例，尚未跑语义模型。
- `presentation_overview.jpg`、`offscreen_memory_overview.jpg`：便于快速查看的静态图。

## 1. 构造：把显示强度、停留时长和可靠性分开

新增 `MultiAgent/attention_volume.py`，统一使用既有 `project_gaze` 和 camera_geometry 变换；不另造时钟，不加载GT，也不投影anchor。

对每个当前查询时刻，过去2秒按旧、中、新三段构造密度。每条观测使用有界时间支持区间，而非按采样条数累加；相邻样本的中点决定支持边界，单边最长0.125秒，缺测间隔不被长时间填满。无效样本切断相邻支持，不补一个假的最小时长。只使用查询之前的观测，未来样本不会改变本次构造。

每个高斯核先归一化到总质量1，再乘支持时长；即便核在图像边界被截断，整张图的质量仍是秒。每个时间段的密度和恰好等于该段视锥内观测的加权时长。

- **时长**：直接保存秒数。
- **空间形状**：用质量覆盖区域、多个连通热点和实际观测代表点描述，避免把两热点之间的平均位置当对象。
- **覆盖**：受支持时长/时间段长度，独立保存。
- **显示**：可以调整空间形状对比度，但强度仍受支持时长限制，不能把一次稀疏观测归一化成“非常确定”。

工程参数为2°核、2秒历史、三段、0.25秒显示支持饱和点；均不是校准过的设备噪声、目标概率或通用最优参数。当前投影仍只验证视锥，不能证明遮挡、动态对应或绝对像素精度。

## 2. 呈现：尽量保留RGB内容

本轮准备了39张查询帧的六种输入。所有模型卡片固定896×480、同一提示、实际420视觉token；左侧为上下文，右侧为呈现，查询位置由脚本角标明确指定。

| 条件 | 处理与目的 |
| --- | --- |
| RGB | 保留RGB和查询角标，作为同位置识别基线 |
| LEGACY_FILLED | 既有2秒历史半透明填色 |
| MASS_CONTOURS | 每个时间段只画覆盖50%和85%密度质量的边界，保留热点内部原色与纹理 |
| MASS_SPOTLIGHT | 使用三段密度控制亮度，关注区保留原色，外围保底55%亮度 |
| CROP_018 | 既有18%边长局部，用于核对新形式是否比简单局部更有效 |
| HEAT_ADAPTIVE_CROP | 保持查询中心不变，由最近受支持时间段的局部80%时长质量决定上下文尺度，边长限制18%–50% |

还生成了独立密度图供脚本/人工诊断，未要求模型把独立图中的热点反查回RGB。旧、中、新仍可用颜色帮助人工浏览，但颜色解码不属于本轮模型任务。

这组比较使用相同的gaze派生查询角标，不能当作“有gaze对无gaze”的因果比较。中心内容识别也不是跨帧对象身份或最终referent准确率。

## 3. 使用：热图可以负责组织证据

新增 `MultiAgent/heatmap_forms_study.py` 与 `tools/report_heatmap_forms_study.py`。每个时间段先由脚本从密度热点中选择实际观测代表点，再生成两种RGB证据：

1. **当前重投影**：把历史点投到当前相机，查看当前RGB局部。
2. **原生历史**：用同一受支持时钟找到该观测当时的视频帧，以实际PTS和对应姿态生成局部。

原生帧按完整解码序列的帧号精确提取，记录实际PTS、与gaze的时间差、视频/遥测/图像哈希。本次18个历史代表点与原生帧的最大绝对时间差约20.93ms，均不晚于当前查询。没有把相近帧当同一帧，也没有省略已有时钟/姿态保护。

模型每次仍只回答 `{"category":"…"}`。脚本把类别与源帧、时间段、支持时长和代表观测绑定，保存 `semantic_attention_evidence.json`。不把一个代表点的类别赋给整个时间段，不把同类别合成同一个对象，不把时长伪装成模型置信度。

### 超过固定三段：按注视变化组织历史

新增 `MultiAgent/attention_memory.py` 与 `tools/build_native_attention_memory.py`。不依赖“过去点目前仍在当前画面中”来保留历史：

- 先在每条观测自己的相机中验证投影，保留时间支持。
- 用世界坐标注视方向变化、有效样本间隔进行工程分段；当前阈值8°，低于0.12秒的段标为支持少。
- 每段保留实际观测代表点、原生RGB、支持时长及替代观测；在当前相机中落到画外也不删除。
- 当前重投影只作为另一个可选诊断。不同段不是对象轨迹，也不是已验证的生理fixation；移动相机平移、有限深度误差和世界坐标假设都会影响分段。

六个固定时序查询生成18段原型；另三个包含画外投影的查询生成16段示例。共34张局部预览未调用模型，不能和下述54次固定三段语义实验混写。

## 4. 实验与结果

### 样本与冻结

此前10交互的30帧全部标为 **regression**，不再当未见验证。额外选取三个此前未用于这些语义调参的交互 scene3/109、scene4_room2/149、scene5/112，每条按受支持帧中的低/高头动和时间中点选3帧，共9帧 **fresh**。fresh仍与旧数据有场景重合，只有三个交互，不能作跨场景或统计显著结论。

六条件及参数、查询位置先冻结；fresh类别和歧义标记由助手在模型输出前复核，保存哈希锁。静态呈现为39×6=234次本地8B请求。

固定三段时序实验取六个交互，每个先按三段最小支持时长选择一个查询；每查询三段、每段三种呈现，共18×3=54次。三种呈现为当前局部、原生局部、当前单段轮廓。它们共享简单类别提示，但**当前与原生图可能显示不同表面，各有独立复核标签**。

所有类别标签是预先冻结的助手视觉复核，**不是人工像素GT、交互referent GT或最终任务准确率**。

### 同一查询位置的呈现比较

| 呈现 | 回归30帧 | 新交互9帧 | 新交互无歧义7帧 |
| --- | ---: | ---: | ---: |
| RGB | 13/30 | 2/9 | 1/7 |
| 旧填色 | 10/30 | 3/9 | 2/7 |
| 质量等值轮廓 | 12/30 | 3/9 | 2/7 |
| 密度聚光 | 12/30 | 3/9 | 2/7 |
| 固定18%局部 | 20/30 | 3/9 | 3/7 |
| 热图决定局部尺度 | 19/30 | 2/9 | 2/7 |

回归结果表明轮廓/聚光没有超过RGB；新交互中一帧的差异不足以证明收益。固定18%在上一轮留出集的优势，也未在本次三个新交互上形成更强证据。自适应尺度没有成为更好的替代品，不能因其更复杂就优先采用。

### 固定三段历史内容识别

| 呈现 | 回归交互9段 | 新交互9段 |
| --- | ---: | ---: |
| 当前RGB局部 | 7/9 | 4/9 |
| 历史原生RGB局部 | 5/9 | 2/9 |
| 当前单段轮廓 | 3/9 | 6/9 |

原生历史的识别也未改善，半透明手仍会被当作目标。当前单段轮廓在新交互为6/9，但在回归只有3/9，且两者内容类别不同，不能挑选较高一列宣布胜出。

18个代表点中，有6个当前与原生图的复核类别集合不相交：例如当前墙面/原生桌面、当前天花板/原生人物。这个内容差异提醒我们保留源帧证据；它不能独立区分时钟、姿态、有限深度、动态对象或标注误差，也不能直接把原生图当作已正确追踪的同一目标。

### 当前视野裁剪会丢失哪些历史

在全部39个查询窗口中，先保留自身相机支持的历史，再与当前相机视锥比较：

- 原生历史累计支持约72.99秒，当前视锥过滤后约65.75秒。
- 9个查询受到影响，保留了66条当前投影画外的**观测—查询配对**，窗口累计支持差约7.24秒。
- 查询窗口有重叠，66不是去重的观测数，7.24秒也不是不重复的视频时长。
- 这9个查询均来自回归帧；fresh九帧本轮没有这种损失。当前视锥判断仍无像素/遮挡GT，不能说这些物体真实不可见。

这是可核对的证据保留差异，不是识别性能提升。它直接支持“当前空间图”和“带源帧的历史记忆”分开保存，避免头动时历史只因当前投影范围而消失。

## 5. 验证与实现边界

- **288/288** 请求完成；每次实际420视觉token；输入tensor进入vision forward均核验；所有输出恰有一个category字段。
- 输入图片、提示、冻结标签/manifest、源代码快照、视频/遥测合同哈希均核对；实际调用审计没有缓存命中或额外调用。
- 39个查询的每段密度质量与支持秒数一致；原生帧时间差、未来帧排除、34张额外预览哈希核验通过。
- **18项针对性测试通过**：包含质量守恒、边界核、弱支持不变强、缺测、无效样本、未来隔离、多热点、合成静态世界点的头动投影、时间反转保留总空间质量而改变时间层、画外记忆保留，以及此前空间孔径/裁剪/选择检查。
- 四个HTML查看器在独立QuickJS临时环境中执行脚本并遍历选择项，检查图片路径。使用最小DOM验证逻辑，**没有完整浏览器视觉回归测试**。

## 6. 后续使用方式

建议继续保留三层：数值时空密度保存“什么时候、分布怎样、支持多少”；可选轮廓用于人和模型的局部定位对照；带原生帧的历史证据供后续mention和对象对应使用。模型负责局部语义，时间归属、支持和源帧引用由脚本给定。

当前更需要人工复核半透明手覆盖、中心物体/邻接物混淆，以及原生与当前不同表面的案例；再在新交互上用真实的对象/mention时间对应任务比较“即时局部序列”和“历史证据”。保留真历史/时间打乱/跨交互错配及等预算RGB对照，分别检验时间信息是否有贡献。原生记忆保留了信息，并不自动代表模型能够正确识别和使用它。本轮没有用类别测试取代最终指代任务，也没有否定所有热图构造的潜力。
