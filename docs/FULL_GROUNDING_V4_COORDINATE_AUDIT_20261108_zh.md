# V4 视觉坐标契约审计（2026-11-08）

本审计只读取冻结的 V4 manifest、源码快照、响应、源帧和复合输入图片，不读取 GT，不调用模型，不调整阈值或 decoder。审计脚本为 `tools/audit_full_grounding_v4_coordinates.py`，机器可读结果为 `.local-sync/full_interaction_referring_20261108/grounding_v4/coordinate_audit.json`。

## 核验结果

- 冻结 V4 manifest 与 protocol lock、V3 父 manifest 与 parent hash 相符；运行时四个关键源码文件和报告均与 `runtime_lock.json` 哈希一致。
- 32/32 冻结响应的 SHA-256 与预测冻结清单一致，32/32 的真实视觉编码器输入消费核验通过。
- 96 张 672×672 源帧哈希通过。384 个复合输入文件均为 1344×1400，文件哈希通过；每张左上区域 `(0,28)-(672,700)` 与对应源 RGB 像素完全一致。
- 因此 whole-composite 0..1000 坐标到左上 RGB 局部坐标的几何映射可直接由文件尺寸和像素布局确定：

```text
x_rgb = (x_composite / 1000 * 1344) / 672
y_rgb = (y_composite / 1000 * 1400 - 28) / 672
```

  RGB 面板在复合坐标中的合法范围为 `x: 0..500`、`y: 20..500`。原始 76 条 grounded 点全部落在该范围。70 条通过行级验证的点以及 70 条 decoder 输入点，均与独立重算坐标逐项一致。合成边界、中心和右下角映射测试通过。
- 处理器审计记录 32/32 禁止二次采帧/重采样；有效 patch-grid 覆盖尺寸均为 1408×1344，视觉编码器输入与处理器 tensor/grid 的逐次匹配核验通过。

## 结论与边界

V4 的复合图到 RGB 坐标换算没有发现实现偏差；现有 V4 冻结预测的坐标映射可复现，因此无需为了坐标问题重跑 V4.2。此前 V4/V4.1 的 GT 评价保持原样，本次没有重新加载 GT 或改写评价结果。

这只能证明坐标落在正确的 RGB 面板并按既定几何转换，不能证明模型点在对象表面、相机投影 anchor 可见、遮挡关系正确或同类实例身份准确。原 decoder 仍是近似 anchor-center 映射。为避免在这 8 条已使用交互上继续调参，下一步应先冻结真正未见的完整交互样本与条件，再用原 evaluator 在预测冻结后做最终集合评分；当前默认 pipeline 不变。
